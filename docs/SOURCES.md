## Туту

Разведка 21.11.2026: 5 загрузок страницы через `probe` + 4 прямых запроса к API. Капчи и ограничений не было. Дампы: `recon/tutu/`.

### Как получать данные

**Основной способ — прямой `POST https://offers-api.tutu.ru/railway/offers` без браузера** (0,5 с, без cookie и токенов, ответ gzip):

```json
{"routes":[{"departureStationCode":"2020500","arrivalStationCode":"2000000","departureDate":"2026-12-05"}],
 "analyticsPassengers":{"adultCount":1,"children":[]},"searchId":"<uuid4>","sessionId":"<uuid4, постоянный>",
 "flags":[{"name":"possibleOffersEnabled","value":"ENABLED"}],"userData":{},"source":"trainOffers"}
```

Заголовки: `Content-Type: application/json`, `Origin`/`Referer: https://www.tutu.ru/`, обычный User-Agent.
Браузер делает тот же запрос плюс `pageId` и флаг `interchangeOffersStrategy=ON_EMPTY_DIRECT_SEARCH` (при пустой прямой выдаче подставляет пересадки — нам не нужен). WebSocket больше не используется, хотя поле в `__NEXT_DATA__` всё ещё называется `websoketUrl`.

**Запасной способ** — открыть страницу выдачи в браузере и перехватить этот же ответ.

### Ответ

JSON-массив из 2–3 элементов одинаковой структуры: первый — варианты с ценой, следующие — без цены (`price.type: "absent"`, классы, которые онлайн не продаются). Разбирать все элементы, брать только `price.type == "exact"`. Готовность = пришёл ответ, «тишину» ждать не нужно.

Цепочка связей внутри элемента `o`:

```
o.offers.actual.<id>                      предложение = поезд
  .routeIds[0] → o.dictionary.common.routes.<id>.segmentIds   (1 сегмент = прямой поезд; >1 — пересадка, отбросить)
  segment = o.dictionary.common.segments.<id>
      departureDateTime / arrivalDateTime  ISO с местным смещением (+03:00, +04:00 Самара) — брать как есть
      duration (мин), departureGeoPointId / arrivalGeoPointId, voyageNumber
  o.dictionary.train.voyages.<voyageNumber>.number            "001Ж" (уже нормальный вид)
  o.dictionary.train.points.<geoPointId>                      вокзал: name.nominative, code (Express), tzName
  .offerVariants[]                                            тариф
      price.value.amount / fraction                           499354 / 100 = 4993.54 ₽
      priceOld.value                                           цена без скидки
      discounts[].discountName                                 "alfa_wallet" и т.п.
      status.saleStatus                                        "ALLOWED"
      fareApplications.<segmentHash>[0] → o.dictionary.common.fareApplications.<hash>
          serviceClass "3Б", seats, passengerType "ADULT"
          segmentConditions → o.dictionary.train.conditions.<id>: carType, seatType (LOWER/UPPER/SIDE_*), refundability
```

Мин. цена класса = минимум `price` по вариантам. Проверено: совпадает со страницей до рубля (001Ж: плацкарт 4906, купе 6976, СВ 25074).

### Классы

`carType` у Туту не совпадает с подписью на сайте: вагон, показанный как «СВ», имеет `carType: LUX`, класс `1Э`. Классифицируем по `serviceClass` (код класса обслуживания), `carType` — запасной признак.

| carType | Встреченные serviceClass | Наш класс |
|---|---|---|
| RESERVED_SEAT | 3Б, 3Э | `platzkart` |
| COMPARTMENT | 2А, 2К, 2Т, 2Ф, 2Ц, 2Ш, 2Э | `coupe` |
| LUX | 1Э, 1Ф (с ценой), 1У (без) | `sv`; настоящий люкс отличать по коду — уточнить |
| SEDENTARY | 2С, 3Ж (без цены) | `seated` |
| SOFT | 1А, 1И, 1М (без цены) | `lux` |
| SHARED | 3О (без цены) | общий — не показываем |

### Цена: две важные особенности

1. **Персональные цены.** Цена зависит от `sessionId`: на один и тот же запрос получено 3183,57 (сессия браузера, как на сайте), 3132,58 (случайная новая сессия) и 3030,59 (без сессии). Разброс около 5%, похоже на A/B-тест наценки. Комиссия, открыв Туту у себя, может увидеть цену на несколько процентов другую.
2. **Скидка банка в показанной цене.** Крупная цена на сайте уже со скидкой `alfa_wallet` (−10% при оплате картой Альфа-Банка). Без карты — `priceOld`.

Методика — решение D-22 (ожидает автора).

### Пустая выдача

`offers.actual == {}`, причина в `warnings[].content` (HTML), например «Мы пока не продаем билеты по этому маршруту» (Калининград). Пустая дата на обычном направлении ещё не встречалась — проверить в фазе 5.

### robots.txt

`www.tutu.ru/robots.txt` запрещает `/*date=` (страница выдачи с датой), `/ajax/`, `/*search`. У `offers-api.tutu.ru` и `train-gateway.tutu.ru` robots.txt нет (404). Прямой запрос к API не трогает запрещённые страницы; браузерный запасной путь — трогает. См. D-23.

### Ответ

`{success, displayLocalTime, infoMsgs, result: [поезд]}`. Поезд: `trainNumber` ("001Ж"), `from`/`to` (`code` — Express, `station`, `metaId`), `departure`/`arrival.isoTime` (ISO со смещением), `durationInMinutes`, `places[]` — по одному на тип вагона:

| Поле | Пример | Смысл |
|---|---|---|

| `serviceClasses` | ["3Б","3Э"] | Коды классов обслуживания |
| `cost` | 5437 | **Цена OneTwoTrip** (мин. по типу, с комиссией) |
| `gdsCost` | 4941.9 | **Цена из системы продажи без комиссии посредника** — фактически тариф перевозчика |
| `commissionAmount` | 495.1 | Комиссия OneTwoTrip |
| `tariffService` | 287.6 | Сервисная часть тарифа |
| `freeSeats`, `placeQuantity.lower/upper/total` | 139 / 26 / 113 | Места |
| `tripCoinsBonusAmount` | 108.74 | Бонусы (не вычитаем) |

Проверено 05.12, 001Ж: OneTwoTrip 5437 / Туту 5451 (без скидок) / `gdsCost` 4941,9. Прибытие 09:30 совпадает с Туту.

Для `User-agent: *` запрещены только `/ru/poezda/faq*/feed*` и `*/trackback*`. `_railways` и выдача не закрыты (`/_api/*` закрыт только для YandexBot).

Правило: **цена РЖД = ⌈`gdsCost` − `tariffService`⌉**. `tariffService` есть только у плацкарта (`selectBedding: true`) — это постельное бельё, которое РЖД в цене «от» не учитывает, а OneTwoTrip включает. РЖД округляет вверх до рубля. Сайт РЖД (и сертификат НУЦ) для базовой цены не нужен.

### Адаптер (фаза 8, 22.11.2026)

- **Цена без белья точно:** `commissionInfo` раскладывает комиссию — `percent_markup` (10% к тарифу без белья), `bedding_markup` (наценка на бельё, 30 ₽), `additional_markup`. Цена OneTwoTrip без белья = `cost − tariffService − bedding_markup` (5437 − 287,60 − 30 = 5119,40 = 4654,30 × 1,1).
- **Нет мест / поездов:** `{"success": false, "error": {"code": 1311, "details": "На заданном направлении (или поезде) мест нет"}}` → пустой день. Другие коды — `layout_changed`.
- **Ссылка на поезд:** `result[].deeplink` ведёт сразу к выбору мест в поезде.
- Работает и с ПК автора (через VPN), и с сервера.
- **Ограничение частоты (22.11, сервер):** после ~100 запросов за 10 минут с одного IP отвечает `{"error": "ATTEMPTS_EXCEEDED", "result": ...}` (без `success`) на всё подряд. Считаем блокировкой → охлаждение 60 мин. Пауза между запросами — 12 с (≤ 5 в минуту).

### Ценность

`gdsCost` даёт базовую цену без наценки посредника в каждом ответе — можно показывать «официальный тариф» и наценку площадок к нему, даже без сайта РЖД.

## Aviakassa

Разведка 21.11.2026 с сервера РФ. Работает без браузера, 0,3–0,5 с на дату. Станции — коды Express, как у Туту.

### Запросы

Общие параметры: `channel_token=` (пусто), `lang=ru`, `uuid=<uuid4 на сессию>`, `partner=AKV4`. Заголовки: обычный UA, `Accept: application/json`, `Referer: https://www.aviakassa.com/zhd`.

| Адрес | Что даёт |
|---|---|

| `GET .../get-trains-list?from=..&to=..&date=ДД.ММ.ГГГГ&time_from=0&time_to=24&lang=ru&adult=1&child=0&infant=0` | Так делает сайт: возвращает `search_id` |

### Ответ

`data.items[]` — поезд: `train_number`, `train_category`, `train_name`, `departure_date_time`, `arrival_date_time` (ISO со смещением, Самара `+04:00`), `trip_duration` (мин, строкой), `passenger_departure_station_code`/`_name`, `passenger_arrival_station_code`/`_name`, `carriers`, `cashback`. `car_groups[]` — тип вагона: `car_type_name` (СВ/КУПЕ/ПЛАЦКАРТ), `car_type` (Luxury/…), `service_classes`, `min_ticket_price`/`max_ticket_price` (рубли, целые), `total_place_quantity`, `lower_/upper_/lower_side_/upper_side_place_quantity`, `service_costs`.

Пример 05.12, 001Ж: СВ 27 946, купе 7 561, плацкарт 5 781 (Туту 5 451, OneTwoTrip 5 437, база 4 942).

### robots.txt

Закрыты страницы `/zhd/results*`, `/zhd/booking*`, `/zhd/checkout*` и др. `/api/v4/` не закрыт. Ссылка для пользователя ведёт на `/zhd/results/...` — это переход человека, не обход роботом.

### Адаптер (фаза 9, 22.11.2026)

- `service_costs` у плацкарта = `[287.6]` — стоимость белья (та же, что `tariffService` у OneTwoTrip); у купе — сервисная часть тарифа (`[861, 1566]`). Цена плацкарта одна (`min = max`), варианта без белья нет → считаем, что бельё включено, и вычитаем его. **Допущение**, проверка — 9.3a.
- `is_component: true` — не пересадка, а поезд, меняющий номер (`357*С`, `345*С`). Не отбрасывать.
- Пустой день: `success: true`, `data.items: []`.
- `book_url` пустой — ссылка ведёт на `/zhd/results/<search_id>`.
- С ПК автора через VPN бывают тайм-ауты (Адлер 22.11); повтор проходит.

## Ozon Travel

**Отложено 21.11.2026.** С ПК автора (подключён VPN) Ozon отвечает 403 и страницей «Похоже, нет соединения. Выключите VPN…» с номером инцидента — и в браузере без окна, и в видимом окне Chrome; даже `robots.txt` закрыт редиректом. Вероятная причина — VPN-адрес. Вернуться при проверке с сервера (1.16–1.17). Если блок останется и без VPN — значит, детектируется автоматизация, и тогда Ozon не берём (D-11).

- Nuxt. Маршрут: `https://www.ozon.ru/travel/railway/volgograd-177578000/moskva-140158000/` (слаг + внутренний ID).
- Первая загрузка может дать «Antibot Challenge Page» (403), JS-проверка проходит сама за несколько секунд; при частых запросах может ужесточиться.
- На странице маршрута цены «от» по классам **без привязки к дате**, выбор даты ведёт в форму поиска.

Главный вопрос — цена на дату. Пути: (1) пройти форму в `probe --headed`, взять итоговый адрес выдачи; (2) найти внутренний запрос выдачи в HAR, вызывать из контекста страницы; (3) запасной — календарь цен маршрута (минимум по дате без поездов).
Проверить также: сохраняется ли пройденная проверка в профиле; сколько загрузок подряд проходит; ID городов через подсказки; время; сбор в цене; `robots.txt`; поведение с серверного IP и через прокси.

Если цену на дату получить нельзя → Ozon только в календаре цен, третий источник становится важнее.

## Правила

Капчи не решаем никак. Не входим в аккаунты. Без стелс-плагинов и подделки отпечатков. Прокси автора используем для стабильной работы с серверного IP, но если площадка показывает капчу — это стоп, а не повод перебирать прокси. Паузы и дневные бюджеты соблюдаем, тяжёлые ресурсы не грузим.
